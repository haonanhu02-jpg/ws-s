# 员工宿舍 8.5 后端契约（阶段 1～4）

## 页面冻结范围

本契约适配 `D:\download\宿舍管理系统\8.5` 现有页面，不改变页面结构、字段、菜单和布局。
前端原 `DM.data.regions[*].rooms[*].beds[*].occupant` 数据改由后端资源树和住宿接口提供。

## 资源模型

- 楼栋：名称、所属区域、启用状态、排序。
- 房间：楼栋、楼层、房号、朝向、房型、是否可住、清洁状态、平面图网格坐标、备注。
- 床位：房间、标签、编码、启用状态、三件套、待打扫状态。住宿记录勾选待打扫时同步标记床位，退宿后仍保留，直至管理员点击“完成打扫”。
- 人员：姓名、中心、部门、性别、人员类别、岗位、职级。
- 住宿：申请单编码、对接人、床位类型、三件套（自带/公司提供/空白）、三件套说明、是否纳入降本、承诺书、床位待打扫状态、入住/退房水电读数、计划/实际入住退宿日期和备注。

各住宿记录独立保存姓名、中心、部门、性别、人员类别、岗位和职级快照。编辑、清空或导入某条住宿记录只更新该记录，不能通过共用人员档案同步到其他房间、宿舍或历史住宿。人员 ID 保留用于住宿历史、缴费等身份关联；人员档案编辑也不回写既有住宿快照。取消/退宿/删除仍按住宿记录 ID 操作，不按姓名或人员 ID 批量操作。升级仅复制当前人员信息为已有住宿的初始快照，不删除或自动合并任何重复住宿记录。

人员类别允许空白；可选值为：基地学习人员、总部临时入住人员、外部合作入住人员、新员工（派驻基地过渡）、新员工(普通)、己审批长住员工。

## 状态

员工页面的预订/入住展示统一依据电脑本地日期和计划入住日判断，数据库原始状态为 BOOKED 或 CHECKED_IN 时均适用；未来入住显示预订，到日显示入住，取消/退宿状态不变。平面图房间与床位颜色、台账、编辑记录列表、统计和导出使用同一展示状态，不因展示纠正而改写实际入住审计。打开床位默认编辑该床位当前展示的住宿记录；连续预订仍可明确选择其他记录。编码缺失预警按具体住宿记录判断，已填编码或入住日期未到不提醒；预警显示入住日期并提供直接编辑该记录的入口。

员工住宿状态独立于访客住宿状态：

`BOOKED -> CHECKED_IN -> CHECKED_OUT`，`BOOKED -> CANCELLED`。

调宿和续住不改变当前入住状态。已预订或已入住记录只在其计划住宿日期内占用床位；同一床位可保存日期不重叠的连续未来预订，日期首尾均计入区间，同日交接视为冲突。标间不得在日期重叠期间男女混住。

## API

统一前缀：`/api/visitor/dormitory/employee`

- `GET /resources/tree`
- `POST /buildings`
- `PUT /buildings/{id}`
- `POST /rooms`
- `PUT /rooms/{id}`
- `POST /beds`
- `PUT /beds/{id}`
- `POST /beds/{id}/cleaning`（标记待打扫或完成打扫）
- `GET /people?name=`、`POST /people`、`PUT /people/{id}`
- `GET /people/{id}/stays`
- `GET /stays?status=&buildingId=&name=`、`GET /stays/{id}`
- `POST /stays/book`
- `PUT /stays/{id}`（编辑预订或在住人员及住宿信息）
- `POST /stays/{id}/check-in`
- `POST /stays/{id}/transfer`
- `POST /stays/{id}/extend`
- `POST /stays/{id}/check-out`
- `POST /stays/{id}/cancel`
- `DELETE /stays/{id}`（仅允许永久删除已取消或已退宿记录，同时清理附件与住宿操作明细）
- `DELETE /people/{id}`（仅允许删除不存在任何住宿记录的人员档案）
- `GET /stay-audits`
- `GET /resource-audits`
- `GET /meter-readings?month=YYYY-MM`
- `PUT /meter-readings`
- `POST /imports/people`（Excel 解析后的人员批量数据，事务导入）
- `POST /imports/resources`（Excel 解析后的楼栋、房间和床位批量数据，事务导入）
- `POST /imports/stays`（完整住宿模板批量导入，包含人员、床位和全部住宿字段）
- `GET /statistics`（床位、楼栋、人员类别和住宿状态统计）
- `GET/POST /stays/{id}/attachments`、`GET/DELETE /attachments/{id}`（住宿附件）
- `GET /fees/settlements?month=&person=&buildingId=`（按月份、人员、宿舍查询员工水电历史结算明细）
- `POST /fees/settlements/generate?month=`（月底批量生成不可修改的员工水电分摊批次）
- `POST /fees/settlements/{batchId}/reverse`（整批冲正；修正后另行生成新批次）

所有写接口从 JWT 用户名取得操作人，不接受客户端伪造操作人。附件限制 10MB，仅允许 PDF、图片、Word、Excel，并保存到持久化卷。水电费仅在月底按房间相邻两月抄表差额批量结算，退房页面不计算单次费用；水费 15 元/吨，电费 0.7 元/度，每间房每月免费电量 5 度。单间或标间独居时由居住人承担，标间同住时按每日实际同住人数分摊；免费电量按当月计费人员实际居住天数比例抵扣。无历史缴费记录人员连续入住不足 15 天时当月免费，达到 15 天后只计当前月份，已免费历史月份不补收；退房后再次入住重新累计。每次生成均追加独立锁定批次，不覆盖历史；修正必须整批冲正后新增。入住人员信息表单的业务字段均为选填，全部留空仍可保存，姓名、部门、性别、人员类别、床位类型、计划入住日期等由服务端写入安全默认值；是否类字段留空按“否”处理。前端完整住宿模板的全部字段均为选填，导入时允许缺少字段或调整列顺序，并按表头名称识别；没有床位编码的行会明确跳过，不自动猜测床位。当前在住及预订台账导出复用完整入住导入模板的字段及顺序，可直接修改后重新导入；基础人员档案导出复用人员导入模板字段。导入导出范围跟随顶部当前楼栋或全集团选择。住宿/退宿确认单打印，以及台账、人员、历史、抄表、员工水电分摊明细和统计数据均可导出 Excel。

统计总览中的有效楼栋、有效房间、有效床位和可入住床位采用同一口径：楼栋必须启用，房间必须启用且可住，床位必须启用。停用楼栋下的房间和床位、停用房间下的床位，即使子级自身仍显示启用，也不进入有效资源及可入住统计。

宿舍导航范围：顶部仅保留全集团及四个平级宿舍，不再显示总部。宿舍顺序为盛心公寓、伏龙宿舍、花城宿舍、岙底罗（万盛空间）。选择宿舍后，统计、平面图、预警、入住台账、历史档案、水电报表和资源设置及其导出均按该宿舍筛选；全集团展示全部宿舍，按上述顺序排列。左侧功能导航随页面滚动保持可见。已有楼栋区域元数据不因导航调整而删除。

2026-10-08 页面规则：降本数据按筛选条件导出完整入住台账字段及统计区间、入住天数。台账及预警按电脑本地日期判断：未来入住为预订，入住日期已到为已入住；终止状态不变。员工入住申请单编码缺失提醒仅在入住日期已到时展示。预订和退房提醒显示楼栋、房号、姓名、中心、部门。停用资源允许维护床位信息，业务字段全部选填；平面图停用床位仅显示填写的姓名，三件套说明星号保留，停用资源仍不计入有效容量。
