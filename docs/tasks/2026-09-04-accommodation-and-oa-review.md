## 已补齐的缺口

1. 扫码登记的是否住宿字段不再在门卫服务写死为 false；继续隔离身份证、部门、事由、电话及床位字段。
2. 门卫每次资料修改均发布 Outbox 事件，包括取消住宿。宿舍更新姓名、电话、被访人和车辆信息；二维码来源的部门/事由保留登记主数据。
3. 独立 detailsVersion 防止过期事件覆盖新资料；eventId 幂等；宿舍确认与床位状态不被资料同步重置。
4. 未确认可取消。正常路径后端查宿舍状态，已确认/分床返回 409，不可核验返回 503。并发确认时宿舍拒绝取消并按版本补偿门卫标记，保留床位。
5. 工作台新增默认入口“访客住宿申请”，真实接口列表、搜索、5 秒刷新、确认住宿。取消后的未确认申请从列表移除。员工台账仍独立。
6. 门卫表单必填星号同排、手机单列、复选项换行、弹窗内显示后端错误。
7. 新增 Flyway V4（门卫）/ V9（宿舍）：历史记录可恢复地重投影，只有没有资料编辑记录的二维码记录从源修复住宿字段，不覆盖手工修改。每批 25 条、间隔 30 秒，失败保留待修复标志重试。
8. CI 前端增加 npm test，防止仅构建而漏跑测试。

## 其他尚未完成 / 上线前必须核验

- 访客床位表与员工床位表是两套资源；本轮只补申请列表与确认，并未实现自动转员工台账、访客分床 UI 或统一床位池。
- 访客 check-in/check-out 仍未启用（Q-013），不能把“已分床”称为真实已入住/已退宿；已确认申请的宿舍撤销操作/审计规则仍需细化。
- 后台登记查询最多读取 200 条，首页今日登记复用该集合，大量登记时会低估。需要服务端按日期计数及完整分页，而非简单扩大 limit。
- 门卫部分操作审计仍信任 X-Operator 请求头，需改为 JWT 身份；本轮没有将其误称为可信审计已完成。
- RabbitMQ 没有数据卷，重建容器存在队列丢失风险；需持久化、发布确认和重放/监控方案。当前 Outbox 发出后标记，不是端到端 exactly-once。
- 上线必须更换测试密码 11111111、JWT/内部令牌和数据库共享账号，配置 HTTPS、网络隔离、备份恢复与日志告警。不要将测试配置直接公网发布。
- 电话模块 Q-001～003、误点纠错 Q-010、去重 Q-011、管理修正 Q-014、保留期限 Q-015 仍未冻结。
- GitHub push 不会自动更新服务器；本轮未访问生产服务器。部署需要更新镜像/代码并启动容器，检查健康状态。
